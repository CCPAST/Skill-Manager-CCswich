## 一、版本概览

本版本聚焦「AI 智能分类的可用性」与「并发安全」两个方向，共包含 4 项功能新增、5 项缺陷修复、2 项内部改进。

核心变化是 AI 智能分类不再绑定单一接口：现在可以读取 cc-switch 中所有已配置的 Provider，任选一个发起分类，并可实时刷新模型列表；同时把最长 120 秒的大模型调用移出全局锁，消除了分类期间整个界面的假死。另一个关键修复是分类顺序表因缺少 `global` 声明而永不更新，导致新建或删除分类后必须重启才能看到结果。

本版本无破坏性变更，可直接覆盖 1.0.0 使用，配置文件与分类数据格式保持兼容。

## 二、更新内容

### 2.1 AI 智能分类支持多 API 接口选择

- 分类弹窗新增「API 接口」下拉框，列出 cc-switch 中所有已配置 API Key 的 Provider，OpenAI 兼容与 Anthropic 兼容两类均支持。
- 当前启用的接口默认选中并置顶，减少每次选择的重复操作。
- 新增后端接口 `GET /api/ai_providers`，返回可用接口清单及其兼容类型。

### 2.2 模型列表一键实时刷新

- 模型下拉框旁新增刷新按钮，点击后调用所选接口的模型列表端点，实时拉取最新可用模型。
- 对 Anthropic 风格接口自动切换为 `x-api-key` 鉴权方式，与 OpenAI 风格的 Bearer 鉴权区分处理。
- 拉取失败时保留原模型列表，并在界面提示具体失败原因，不打断当前分类流程。
- 新增后端接口 `POST /api/ai_models`。

### 2.3 Anthropic 兼容接口的模型映射解析

- 修正 claude-desktop 类型 Provider 的模型列表来源：改为从 `providers.meta` 的 `claudeDesktopModelRoutes` 路由映射读取。此前误用兜底模型，导致配置中映射的模型完全不显示。
- `labelOverride` 作为显示别名，界面统一渲染为「别名（实际模型）」，避免同类模型因命名差异无法辨识。
- 补充兜底逻辑：路由映射缺失时读取环境变量中的 `ANTHROPIC_MODEL`。

### 2.4 模型下拉支持任意已刷新模型名

- 下拉候选项不再局限于 cc-switch 原有的 modelCatalog，刷新出的任意模型名均可直接选用并提交分类请求。

## 三、修复项

### 3.1 新建或删除分类后界面不更新（严重）

`_assign`、`_newcat`、`_delcat` 三个函数在重新赋值模块级分类顺序表 `_cat_order` 时缺少 `global` 声明，导致赋值实际创建了局部变量，模块级顺序表永不更新。表现为界面必须重启服务或重新扫描后才能看到分类变更。已补全 `global` 声明，分类变更即时生效。

### 3.2 base_url 重复拼接版本路径

当 Provider 的 base_url 自带版本路径时（例如智谱的 `/api/paas/v4`），此前会再拼接一次 `/v1`，产生无效地址。已改为检测 base_url 是否已包含版本段，未包含时才追加；该修正对 chat/completions、messages、models 三个端点统一生效。

### 3.3 AI 调用期间界面假死

`/api/ai_classify` 与 `/api/ai_models` 此前持有服务全局锁，而大模型调用最长可达 120 秒，期间所有其它请求被阻塞，界面表现为无响应。已改为细粒度锁结构，按「快照输入 → 无锁网络 I/O → 校验写回」三段执行：读取阶段短暂持锁取数据快照，网络请求阶段完全释放锁，结果落盘前重新取锁并校验快照是否已被修改。

### 3.4 CLI 合计行统计口径不一致

`skill_manager.py list` 缺少「未分类」独立行，且合计行按分类累加，同一 skill 归入多个分类时会重复计数导致虚增。已新增「◆ 未分类」行，合计行改为按全库 skill 去重统计。

### 3.5 前端两处边界提示缺失

- AI 分类范围选择「当前分类」但未选中具体分类时，此前请求被静默丢弃；现在提前拦截并给出明确提示。
- 接口列表拉取失败时，此前仅显示笼统失败；现在显示具体错误原因。

## 四、改进与优化

- **CLI 写入原子化**：`skill_manager.py` 的 `save_categories` 改为临时文件加 `os.replace` 的原子写，与 Web 端保持一致，防止写入中断损坏 `categories.json`。
- **加载反馈**：刷新模型列表按钮增加旋转加载动画；切换接口时自动联动刷新模型列表与接口信息提示，降低误操作概率。

## 六、升级说明

1. 退出正在运行的旧版本（关闭本地服务窗口或结束对应 Python 进程）。
2. 用本版本文件覆盖旧版本目录，`categories.json` 与 cc-switch 数据库无需迁移，直接沿用。
3. 双击 `技能分类管理器.bat` 启动，访问 `http://127.0.0.1:8765/`。
4. 若此前自定义过分类，覆盖前先备份 `categories.json`，覆盖后放回即可。

从 1.0.0 升级无需改动任何配置。新增的两个 HTTP 接口为增量能力，不影响既有调用。

## 七、已知问题

1. **与 cc-switch 并发写入冲突**：本工具直接写 cc-switch 数据库的启用标记。点「应用修改」前必须先退出 cc-switch（托盘图标右键退出），否则可能触发数据库写冲突。当前版本未实现运行状态检测与写入前拦截。
2. **依赖 cc-switch 数据库结构**：Agent 开关与 cc-switch `skills` 表的 `enabled_*` 列一一对应。若上游 cc-switch 发生表结构级变更，需要同步适配，本版本未做字段缺失的兼容降级。
3. **AI 分类强依赖外部 Provider**：需在 cc-switch 中至少配置并启用一个兼容 Provider。未配置时分类入口会提示「未找到可用的 AI 接口配置」，本工具不内置任何模型或密钥。
4. **模型列表刷新依赖接口实现**：模型列表端点由第三方网关实现，部分网关未提供或返回格式不符。此时刷新失败并回退到 cc-switch 原有 modelCatalog，不影响已有模型的使用。
5. **单次分类超时上限**：大模型调用超时固定为 120 秒，超时后本次分类任务整体失败，不按批次重试。首次识别大量未分类 skill 时建议分批处理。
6. **服务端口固定**：默认监听 8765。若被占用，需手动修改 `server.py` 中的 `PORT` 常量，当前版本未提供启动参数或环境变量覆盖。
7. **分类文件无文件锁**：`categories.json` 的单次写入是原子的，但同时运行 Web 界面与 CLI 并并发修改时，后写入者覆盖先写入者，冲突不会报错。
